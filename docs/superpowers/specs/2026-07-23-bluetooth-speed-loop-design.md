# 蓝牙调节双轮速度环设计

日期：2026-07-23

## 目标

在现有 `NUEDC_2026_MSPM0G3507_BoardTest-main` 工程中加入可通过 UART0 蓝牙链路调节的左右轮速度闭环。保持 2026 主控板既有引脚、MSPM0 SDK 2.05.01.x、SysConfig 1.24.x 和 CCS 工程布局，不启用去年 `timer.c` 中整套竞赛任务状态机。

本功能的速度单位暂定为“每 50 ms 的编码器增量”。在编码器每转脉冲数、减速比和车轮周长未确认前，不对外标称 RPM、rad/s 或 m/s。

## 已确认的本地硬件与软件事实

- 蓝牙使用 `UART_0` / UART0，PA10 为 MCU TX，PA11 为 MCU RX，9600 8N1。
- 左电机 PWM 为 TIMA0 CC0/PB14，方向为 PB9/PB10；右电机 PWM 为 TIMA0 CC1/PA7，方向为 PB7/PB6。
- 左编码器为 PB26/PA13，右编码器为 PB5/PB4。
- 当前主循环只做 100 ms 编码器板测采样，PID 没有初始化，也没有闭环输出。
- 旧工程曾以 50 ms 周期和增量式 PID 运行双轮控制，已使用的初始参数为 Kp=1.37、Ki=0.40、Kd=0.15。
- 当前蓝牙调参代码默认关闭；直接开启会在 UART ISR 中解析数据，并且参数映射错误，不能直接使用。

## 方案比较

### 方案 A：主循环调度的独立双轮速度环（采用）

保留当前 UART0 和 SysConfig 配置。UART ISR 只把收到的字节放入有界环形缓冲；`Bluetooth_Poll()` 在主循环解析完整命令并更新待用参数。`motor_test_tick()` 统一拥有编码器快照、PID 计算和 PWM 输出，每 50 ms 执行一次速度闭环。

优点：改动集中、不把复杂解析放进 ISR、不与旧任务状态机争用 PWM/编码器，能够用主机侧单元测试覆盖协议和控制逻辑。

### 方案 B：启用现有 TIMA1 和 `timer.c`

不采用。`TIMER_TICK_INST_IRQHandler()` 会调用去年保留的 `task1()` 到 `task5()`，其中包含循迹、舵机、激光和多处电机控制。它会与当前 `motor_test_tick()` 重复清空编码器计数并争用 PWM。

### 方案 C：仅开启 `BLUETOOTH_ENABLE_PID_TUNING`

不采用。旧映射将 P1/I1/D1 写入舵机 PID，将 P2/I2/D2 只写入左电机；解析器格式脆弱、没有范围检查，并可能在 UART ISR 中运行解析和 PID 更新。

## 模块职责

### `bsp_hc05.c/.h`

- UART0 ISR：读取 RX 字节并压入单生产者/单消费者环形缓冲；溢出只计数并丢弃新字节。
- 主循环：从环形缓冲取字节，忽略帧外 CR/LF，遇到 `!` 后解析一帧。
- 协议解析：校验命令名、等号、数字格式、长度和范围；无效帧不得改变控制状态。
- 回复：成功返回短 `OK!`，错误返回短 `ERR,<原因>!`；`Q!` 返回一次六字段状态；`CSV=1!` 以 5 Hz 输出六字段整数 CSV，默认关闭。
- 不在 ISR 内发送、格式化字符串、更新 OLED 或运行 PID。

### `motor_test.c/.h`

- 保留原有 8 档开环板测模式。
- 新增独立的速度闭环使能状态；启用闭环时，开环板测模式归零。
- 每 50 ms 原子获取左右编码器增量，按实际经过时间折算为“计数/50 ms”，更新两路 PID 并写入左右 PWM。
- 设置目标、增益或启停均由公开 API 完成；目标为零或执行停止时立即将对应 PWM 置零并清运行历史。
- 速度环运行时只有该模块可以清空编码器周期计数和写闭环 PWM。

### `pid.c/.h`

- `pid_init()` 同时初始化模式、增益和全部运行状态。
- 新增只清误差、积分和输出历史但保留配置/目标的状态复位函数。
- 继续使用去年双轮速度环采用的增量式 PID，并保留输出限幅 ±190，与当前 PWM 公开范围匹配。

### `encoder.c/.h`

- 将 50 ms 周期内不可能溢出的临时计数收窄为 32 位。
- 快照和清零时进入短临界区，避免 GPIO ISR 与主循环竞争造成丢脉冲。

## 蓝牙协议

帧以 ASCII `!` 结束。兼容参考工程的八个字段，同时把两组参数重新定义为左右轮两个速度环：

| 命令 | 作用 | 合法范围 |
| --- | --- | --- |
| `P1=<v>!` | 左轮 Kp | 0..20 |
| `I1=<v>!` | 左轮 Ki | 0..10 |
| `D1=<v>!` | 左轮 Kd | 0..20 |
| `It=<v>!` / `T1=<v>!` | 左轮目标速度 | -200..200 计数/50 ms |
| `P2=<v>!` | 右轮 Kp | 0..20 |
| `I2=<v>!` | 右轮 Ki | 0..10 |
| `D2=<v>!` | 右轮 Kd | 0..20 |
| `Ot=<v>!` / `T2=<v>!` | 右轮目标速度 | -200..200 计数/50 ms |
| `T=<v>!` | 同时设置左右目标 | -200..200 |
| `RUN=1!` | 启动闭环 | 仅接受 1 |
| `RUN=0!` | 暂停闭环并保留目标，清 PID 运行状态 | 仅接受 0 |
| `STOP!` | 立即停车、目标归零并清 PID 运行状态 | 无 |
| `Q!` | 返回一次状态 | 无 |
| `CSV=1!` / `CSV=0!` | 开关 5 Hz 状态流 | 0 或 1 |

数字允许可选负号、整数和小数，不依赖固定两位小数。帧最大长度限制为 31 个字符；超长、NaN/Inf、缺少数字、负增益或越界值均返回错误且不生效。

六字段状态顺序保持参考工程习惯，但语义改为左右轮：

```text
left_target,left_actual,left_output,right_target,right_actual,right_output\r\n
```

## 状态与安全行为

- 上电默认闭环关闭，PWM 为零。
- 修改目标和 PID 参数不会自动启动电机，必须显式发送 `RUN=1!`。
- `RUN=0!` 立即将两路 PWM 置零并清 PID 历史，但保留目标；`STOP!` 和原有 `motor_test_stop()` 还会把两路目标归零。
- 启用闭环后再切换原有开环板测档位，会先关闭闭环，避免两个控制源同时写 PWM。
- 本阶段不把参数写入 Flash；复位后恢复编译时默认值，避免未经验证的参数永久保存。
- 不使用 `Bluetooth_ConnectFlag` 做断连停车，因为当前硬件没有可靠连接状态输入，UART 静默也不能区分断连和用户观察数据。

## 测试与验证

1. 主机侧 C 测试先行：
   - 正确解析八个兼容命令、整数/小数/负数和别名。
   - 拒绝畸形、超长和越界命令，且状态不改变。
   - `RUN/STOP/CSV/Q` 行为与回复正确。
   - 50 ms 调度、左右轮独立 PID、反向目标、零目标停车和延迟周期归一化正确。
2. 运行 SysConfig 静态检查；本设计不修改 `.syscfg` 或生成文件。
3. 用本机 GCC 跑主机测试，并用 ARM GNU 编译器对改动源码做 Cortex-M0+ 语法检查。
4. 如 CCS 可用，按 `.cproject` 的 SDK 2.05.01/SysConfig 1.24 重新生成 Debug 构建文件后完成全量构建。当前复制来的 `Debug/makefile` 硬编码不存在的 SDK 2.11/旧路径，不能作为可复现构建依据。
5. 硬件验证顺序：架空车轮并限流，先 `STOP!`，确认左右编码器正向符号，再以低目标单轮、双轮测试，最后逐项调整 PID 并观察 CSV/OLED。
